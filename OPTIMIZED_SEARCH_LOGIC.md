# Логика поиска производителей

## Обзор

Движок (`backend/app/services/optimized_search_engine.py`) определяет производителя по артикулу,
минимизируя трафик и расход токенов OpenAI. Этапы называются так же, как в интерфейсе и в
параметре `stages` API: `Internet` → `googlesearch` → `OpenAI`. Каждый следующий этап
запускается только если уверенность после предыдущего недостаточна.

| Модуль | Назначение |
| --- | --- |
| `manufacturers.py` | Справочник ~180 производителей: домены, алиасы (EN/RU/CN/JP/KR), дочерние бренды, страна и профиль; нормализация названий, сравнение артикулов |
| `search_providers.py` | Провайдеры: SerpAPI, Google CSE (API) и бесплатные Yahoo, Bing, DuckDuckGo, Google (HTML-выдача) |
| `evidence.py` | Извлечение признаков («улик») производителя из выдачи и документов, агрегация и ранжирование |
| `document_parser.py` | Потоковая загрузка страниц/PDF с лимитами, разбор в отдельном потоке |
| `ai.py` | Запрос к OpenAI с ответом в JSON (совместим с моделями, требующими `max_completion_tokens`) |
| `manufacturer_service.py` | Запись производителей в БД, справочная информация (справочник → БД → OpenAI, с кешем) |

## Этапы

### 0. Кеш

Если артикул уже определён, а подсказка оператора совпадает с найденным производителем
(или не указана), результат возвращается из БД без внешних запросов (`search_stage = "cache"`).
Если в запросе указан `stages`, кеш игнорируется.

### 1. Internet

1. Запросы `<артикул> <подсказка>` и `<артикул>` выполняются **параллельно** у первого доступного
   провайдера: SerpAPI (если задан `SERPAPI_KEY`) → Yahoo → Bing → DuckDuckGo → Google
   (порядок бесплатных задаётся `WEB_SEARCH_PROVIDERS`).
2. Выдача без единого упоминания артикула считается мусорной (капча, анти-бот выдача Bing/Yahoo):
   она не кешируется, запрос повторяется у следующего провайдера, а провайдер, дважды подряд
   вернувший мусор там, где другой нашёл артикул, отключается на 10 минут. Капча, заглушка
   «включите JavaScript» (Google) и страницы проверки ботов распознаются сразу.
3. Анализируются только метаданные выдачи (0 байт дополнительного трафика):
   * официальный домен производителя + артикул в URL/заголовке/сниппете;
   * сегменты URL дистрибьюторов: `digikey.com/.../detail/stmicroelectronics/LM317T/`;
   * заголовки карточек: `LM317T STMicroelectronics | Mouser`, `LM317T Datasheet (PDF) - STMicroelectronics`;
   * поля `Manufacturer:` / `Производитель:` / `Brand:` в сниппетах;
   * упоминания известных производителей рядом с артикулом (с учётом границ слов, поэтому
     «intelligent» не даёт Intel).
4. Если уверенность < 0.8, параллельно выполняется запрос `<артикул> datasheet` и скачиваются
   3–4 самых информативных документа (PDF/даташиты, страницы производителя; сайты, блокирующие
   ботов, и маркетплейсы пропускаются). Бюджет — 8 секунд на пачку. Из документов извлекаются
   копирайты (`© 2016 Texas Instruments`), поля производителя и упоминания рядом с артикулом.
   Из PDF читаются только первые три и последняя страницы.
5. Этап успешен при уверенности ≥ 0.75.

### 2. googlesearch

Google Custom Search API (если заданы `GOOGLE_CSE_API_KEY` и `GOOGLE_CSE_CX`), только при
уверенности < 0.75. Результаты добавляются к уже собранным признакам. Порог успеха — 0.67.

### 3. OpenAI

Запускается, только если уверенность < 0.8 (или этап выбран явно). Модель получает компактный
контекст — около 8 самых релевантных сниппетов, выдержки из документов вокруг артикула и
эвристических кандидатов (~1000 токенов на вход, до 160 на выход) — и отвечает JSON:

```json
{"manufacturer": "STMicroelectronics", "confidence": 0.9, "source_url": "https://...", "reason": "..."}
```

Ответ, подтверждённый выдачей, получает высокий вес; неподтверждённый — пониженный. Если этап
запущен отдельно (кнопка «OpenAI»), перед запросом выполняется один заход веб-поиска для контекста.

## Агрегация признаков

* Вес признака зависит от типа (официальный домен 0.9, URL дистрибьютора 0.6, заголовок
  карточки 0.55, упоминание в сниппете 0.35 …) и точности совпадения артикула
  (точное — 1.0, с суффиксом исполнения `LM317TG` — 0.75, базовая серия `LM317` — 0.5).
* Признаки с одного домена не суммируются (берётся максимум), голоса разных доменов объединяются
  как независимые: `S = 1 − Π(1 − w)`.
* Итоговая уверенность лидера снижается, если у второго кандидата сопоставимая поддержка —
  так честно отражаются детали нескольких производителей (LM317T выпускают ST, TI и onsemi).
* Подсказка оператора выбирается, если она подтверждена заметными признаками
  (поддержка ≥ 0.35 и не меньше половины поддержки лидера).
* Ниже 0.45 производитель не считается найденным (статус `pending` при наличии подсказки).

## Сопоставление с подсказкой

Названия приводятся к каноническому виду: алиасы (`TI` → Texas Instruments), CJK-названия,
транслитерация (`Сибеко` → Sibeco), юридические суффиксы (`Inc.`, `GmbH`, `ООО`), лишние слова
(`Murata Electronics`, `NXP USA Inc`), дочерние бренды (Linear Technology → Analog Devices,
считается совпадением). Статус: `matched` при сходстве ≥ 0.75, иначе `mismatch`.

Артикулы сравниваются без учёта регистра, пробелов, дефисов и точек; кириллические буквы,
похожие на латинские (`КМ1234` в русской раскладке), приравниваются к латинским. Артикул не
засчитывается внутри чужого номера (`5935-0560-0001` ≠ `0560-0001`).

## Производительность

* Параллельно ищутся до `SEARCH_CONCURRENCY` артикулов (по умолчанию 4), одинаковые позиции
  в пакете ищутся один раз. Все сетевые операции идут параллельно, а обращения к одной сессии
  БД сериализуются блокировкой; результат каждого артикула фиксируется отдельным коммитом.
* Общий HTTP-клиент с keep-alive, кеш удачных ответов поисковиков на час.
* Справочная информация о производителе (страна, продукция, сайт) берётся из справочника или
  из ранее найденных записей; OpenAI вызывается только для неизвестных производителей, и
  параллельные запросы по одному производителю объединяются.
* Замер на реальной выдаче (12 артикулов, без OpenAI): 11 определены верно, ~15 с на весь пакет;
  повторный поиск из кеша — ~0.01 с.

## API

```http
POST /api/search
{
  "items": [{"part_number": "LM317T", "manufacturer_hint": "ST"}],
  "debug": true,
  "stages": null
}
```

* `stages: null` — все нужные этапы с использованием кеша;
* `stages: ["OpenAI"]` (или `["googlesearch"]`, `["Internet"]`) — только выбранные этапы без кеша.

Каждый результат содержит `stage_history` (`name`, `status` = `success` / `low-confidence` /
`no-results` / `skipped`, `provider`, `confidence`, `urls_considered`, `message`). При
`debug: true` в `debug_log` записываются запросы, провайдеры и кандидаты с признаками.

## Уведомления

Если настроен Telegram (страница «Настройки» администратора), в фоне отправляются уведомления
(не чаще раза в час для одного типа): ошибка авторизации OpenAI, исчерпание квоты OpenAI,
блокировка платных API (SerpAPI, Google CSE) из-за неверного ключа или лимита.
