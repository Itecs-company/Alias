# AliasFinder Platform

AliasFinder — комплексное решение для поиска производителя по артикулу (и его алиасам) с современной веб-админкой, API и поддержкой импорта/экспорта данных.

## Возможности

- 🔍 **Интеллектуальный поиск**: этапы `Internet` (SerpAPI при наличии ключа, иначе бесплатные Yahoo → Bing → DuckDuckGo → Google) → `googlesearch` (Google Custom Search) → `OpenAI`. Каждый следующий этап запускается только при недостаточной уверенности; признаки из всех источников (официальный домен, карточки дистрибьюторов, даташиты) агрегируются в единую оценку. Типичный артикул определяется за 1–3 с без обращения к OpenAI.
- 🧠 **Парсинг документов**: при необходимости параллельно скачиваются 3–4 самых информативных документа (потоково, с лимитом размера; из PDF — только первые и последняя страницы) и анализируются копирайты, поля «Manufacturer:», упоминания рядом с артикулом.
- 🎯 **Точность брендов**: справочник ~180 производителей (домены, алиасы на EN/RU/CN/JP/KR, дочерние бренды: Linear Technology → Analog Devices), поиск упоминаний с учётом границ слов, сравнение артикулов без учёта пробелов/дефисов и кириллических «двойников» латинских букв, транслитерация подсказок (`Сибеко` = `Sibeco`). Для деталей нескольких производителей (например, LM317T) подсказка оператора используется как решающий голос, если её подтверждает выдача.
- 🗄️ **Централизованная база**: результаты сохраняются в БД с историей и логами.
- 🌐 **Современный UI**: фронтенд на Vite + React + Material UI, стеклянные карточки, прогресс-таймлайн, светлая/тёмная тема и адаптивный дизайн.
- 🐞 **Режим отладки**: отдельная кнопка включает отображение детальных логов в интерфейсе и передаёт флаг на бэкенд.
- 🔐 **Встроенная авторизация**: обязательный вход через токены (оператор `admin/admin`, администратор `admin/Admin2025`), возможность смены логина/пароля операторов прямо из UI.
- ➕ **Добавление данных** тремя способами:
  1. Ручной ввод в веб-интерфейсе.
  2. Через REST API (`POST /api/parts`).
  3. Загрузка Excel/CSV-файла (минимум колонки `Article` и `Manufacturer/Alias`; повторяющиеся строки объединяются, файл экспорта можно загрузить обратно).
- 📤 **Экспорт** результатов в PDF и Excel из веб-интерфейса и по API (формат соответствует таблице в UI: `Article`, `Manufacturer`, `Alias`, `Submitted`, `Match`).
- ✅ **Сопоставление подсказок**: сервис сравнивает введённый оператором `Manufacturer/Alias` с найденным производителем (совпадает / расхождение / ожидает проверки) и показывает статус в UI, экспорте и базе.

## Архитектура

```
Alias/
├── backend/        # FastAPI + SQLAlchemy + async сервисы поиска
│   ├── app/
│   │   ├── api/    # REST-маршруты
│   │   ├── core/   # конфигурация и подключение БД
│   │   ├── models/ # модели БД
│   │   ├── schemas/# Pydantic-схемы
│   │   └── services/ # поисковые движки, импортеры, экспортеры
├── frontend/       # Vite + React + Material UI интерфейс оператора
└── README.md       # текущий файл
```

Бэкенд использует SQLite (по умолчанию) и асинхронный SQLAlchemy. При старте автоматически создаёт схему и добавляет недостающие колонки в существующий volume (например, после обновления образов), поэтому повторная инициализация БД не требуется.

## Развёртывание

### Вариант A. Docker Compose

Самый быстрый способ поднять полный стек — использовать Docker Compose.

```bash
# один раз скопируйте и отредактируйте настройки
cp backend/.env.example backend/.env

# при первом запуске соберите образы и стартуйте сервисы
docker compose up --build
```

После старта:

- Backend FastAPI доступен на http://localhost:8000
- Web-интерфейс (Vite dev server) на http://localhost:5173
- Фронтенд обращается к API по адресу из переменной `VITE_API_BASE_URL`.
  В контейнерном запуске значение установлено в `/api`, и Vite проксирует запросы к сервису backend.
  Если переменная указывает на `localhost`, а UI открыт по другому адресу, клиент автоматически
  переключится на `http://<адрес_UI>/api`, поэтому дополнительных правок не требуется.

Логи обоих сервисов выводятся в консоль Docker Compose. Данные (SQLite, экспорты PDF/Excel) сохраняются в volume `backend_data`, поэтому не пропадут между перезапусками. Для обновления кода достаточно пересобрать образы: `docker compose build`.

> `backend/Dockerfile` основан на `python:3.11`, устанавливает `httpx[socks]` (все HTTP-клиенты — поисковики, OpenAI, загрузка документов — могут работать через SOCKS5-прокси из `.env`) и шрифт DejaVu для кириллицы в PDF.

### Вариант B. Локальное окружение

#### 1. Подготовка окружения

```bash
# Клонировать и перейти в каталог проекта
cd Alias

# Backend
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# отредактируйте .env, см. раздел «Переменные окружения»

# Frontend
cd ../frontend
npm install
```

#### 2. Запуск сервисов

```bash
# Backend (из каталога backend)
uvicorn app.main:app --reload

# Frontend (из каталога frontend)
npm run dev
```

Приложение будет доступно по адресу http://localhost:5173, API — http://localhost:8000.

### Переменные окружения

`backend/.env` — основной файл конфигурации:

| Имя | Описание |
| --- | --- |
| `APP_NAME` | Название приложения в Swagger/интерфейсе |
| `DEBUG` | `true` включает подробные логи и echo SQL |
| `DATABASE_URL` | Строка подключения SQLAlchemy (по умолчанию SQLite) |
| `SERPAPI_KEY` | (Опционально) ключ SerpAPI для дополнительного Google-поиска |
| `SERPAPI_SEARCH_ENGINE` | Имя поискового движка SerpAPI (по умолчанию `google`) |
| `GOOGLE_CSE_API_KEY` | API-ключ для Google Custom Search |
| `GOOGLE_CSE_CX` | Идентификатор поисковой машины (cx) для Google Custom Search |
| `OPENAI_API_KEY` | Ключ OpenAI для fallback-поиска |
| `OPENAI_MODEL_DEFAULT` | Модель OpenAI, используемая для поиска (по умолчанию `gpt-4.1`) |
| `OPENAI_BALANCE_THRESHOLD_USD` | Устаревшая настройка (API баланса OpenAI недоступен по обычному ключу); об исчерпании квоты сообщает Telegram-уведомление |
| `WEB_SEARCH_PROVIDERS` | Бесплатные поисковики в порядке приоритета (по умолчанию `yahoo,bing,duckduckgo,google`) |
| `SEARCH_CONCURRENCY` | Сколько артикулов из одного запроса ищутся параллельно (по умолчанию 4) |
| `PROXY_HOST`/`PROXY_PORT` | SOCKS5 прокси для исходящих запросов SerpAPI/Google/OpenAI |
| `PROXY_USERNAME`/`PROXY_PASSWORD` | Учетные данные прокси (если требуются) |
| `ALLOW_INSECURE_SSL` | Если `true`, httpx отключает проверку сертификатов (используйте только в доверенных сетях) |
| `ALLOWED_ORIGINS` | Разрешённые Origin для CORS (строка через запятую **или** JSON-массив) |
| `STORAGE_DIR` | Каталог для экспорта файлов (по умолчанию `storage/`) |
| `AUTH_SECRET_KEY` | Секрет подписи JWT-токенов авторизации |
| `AUTH_ACCESS_TOKEN_EXPIRE_MINUTES` | Срок жизни токена (по умолчанию 90 минут) |
| `DEFAULT_USER_USERNAME` / `DEFAULT_USER_PASSWORD` | Начальные учётные данные оператора (создаются при старте) |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | Пара логин/пароль администратора, который может менять данные операторов |

`frontend` читает настройки напрямую из переменных с префиксом `VITE_` во время запуска Vite.
Главная переменная — `VITE_API_BASE_URL`. Если она не задана или указывает на `localhost`, UI автоматически
использует `http(s)://<текущий_хост>/api`. Чтобы задействовать встроенный прокси дев-сервера (Docker Compose
и локальный запуск), достаточно указать `VITE_API_BASE_URL=/api`.

#### Настройка ключей

1. **SerpAPI (необязательно)**: зарегистрируйтесь на https://serpapi.com, создайте ключ и вставьте в `SERPAPI_KEY`, чтобы добавить ещё один источник Google-результатов.
2. **Google Custom Search**: получите API-ключ (https://developers.google.com/custom-search/v1/overview) и идентификатор поисковой машины `cx`, пропишите их в `GOOGLE_CSE_API_KEY` и `GOOGLE_CSE_CX`.
3. **OpenAI**: создайте ключ на https://platform.openai.com и укажите его в `OPENAI_API_KEY`. При необходимости измените `OPENAI_MODEL_DEFAULT` (по умолчанию `gpt-4.1`) и задайте `OPENAI_BALANCE_THRESHOLD_USD`, чтобы получать предупреждения в логах при низком остатке средств.
4. **SOCKS5-прокси**: пропишите `PROXY_HOST`, `PROXY_PORT`, а также `PROXY_USERNAME`/`PROXY_PASSWORD`, если провайдер требует аутентификацию (например, `PROXY_HOST=194.5.62.55`, `PROXY_PORT=17668`). Один и тот же прокси используется всеми HTTP-клиентами (SerpAPI, Google Custom Search, парсер документов и OpenAI).

### Аутентификация и роли

- **Оператор по умолчанию**: `admin / admin` (`DEFAULT_USER_USERNAME`/`DEFAULT_USER_PASSWORD`). С его учётной записью можно выполнять поиск, импорт и экспорт, но нельзя менять пароль.
- **Администратор**: `admin / Admin2025` (`ADMIN_USERNAME`/`ADMIN_PASSWORD`). Только эта учётная запись открывает в UI карточку «Управление доступом», настройки Telegram-уведомлений и endpoint `/api/auth/credentials`, позволяющий задать новый логин/пароль операторов.
- Пароли берутся только из `.env` — встроенных «запасных» паролей нет. **Обязательно смените `AUTH_SECRET_KEY`, `ADMIN_PASSWORD` и `DEFAULT_USER_PASSWORD` в продакшене** (при старте с настройками по умолчанию в логе выводится предупреждение).
- Учётная запись оператора создаётся при первом запуске (когда таблица пользователей пуста). После изменения данных администратором новые логин/пароль действуют сразу и сохраняются после перезапуска, а старые перестают работать.
- Все маршруты `/api/*` (поиск, импорт, экспорт, скачивание) требуют заголовок `Authorization: Bearer <token>`, который возвращает `POST /api/auth/login`.
- Для проверки токена можно вызвать `GET /api/auth/me`.

Пример авторизации через API:

```http
POST /api/auth/login
Content-Type: application/json

{ "username": "admin", "password": "admin" }
```

Ответ:

```json
{
  "access_token": "<JWT>",
  "token_type": "bearer",
  "username": "admin",
  "role": "user"
}
```

Подставьте полученный токен в `Authorization: Bearer` для всех дальнейших запросов.

### 4. Импорт через API

> Во всех примерах ниже требуется заголовок `Authorization: Bearer <token>`, полученный через `/api/auth/login`.

#### Ручное добавление

```http
POST /api/parts
Content-Type: application/json

{
  "part_number": "TPS7A4700",
  "manufacturer_hint": "TI"
}
```

Ответ: объект с найденным производителем и метаданными.

#### Пакетный поиск

```http
POST /api/search
Content-Type: application/json

{
  "debug": true,
  "items": [
    { "part_number": "TPS7A4700", "manufacturer_hint": "Texas" },
    { "part_number": "AD620", "manufacturer_hint": "Analog" }
  ]
}
```

`debug: true` включает расширенные логи в ответе (запросы, провайдеры, кандидаты и их признаки) и сохраняет их в базе.

Необязательное поле `stages` (`["Internet"]`, `["googlesearch"]`, `["OpenAI"]` или их комбинация) выполняет только указанные этапы и **игнорирует кеш** — так работают кнопки «Google» и «OpenAI» в интерфейсе. Без `stages` ранее найденные результаты берутся из БД мгновенно. Интерфейс отправляет выбранные строки пачками по 5, поэтому таблица заполняется постепенно, а ошибка одной пачки не прерывает весь поиск.

#### Загрузка Excel

```http
POST /api/upload
Content-Type: multipart/form-data

file=@aliases.xlsx
debug=true
```

Файл должен содержать лист с колонками `Article` (артикул) и `Manufacturer/Alias` (подсказка по бренду/алиасу). Старый формат с `part_number`/`manufacturer_hint` также поддерживается для обратной совместимости.
Поддерживаются также CSV и колонки `Req.Mnfc`, `Brand`, `Производитель`. Числовые артикулы сохраняются без `.0`, повторяющиеся строки объединяются, повторная загрузка того же артикула обновляет подсказку, а не создаёт дубликат. Некорректный файл возвращает `400` с описанием ошибки.

#### Экспорт

- `GET /api/export/pdf`
- `GET /api/export/excel`

Ответ содержит URL (`/api/download/...`), по которому файл скачивается с заголовком `Authorization` (или `?token=`). В UI файл скачивается автоматически. Каталог `storage/` напрямую не публикуется.

### 5. Web-интерфейс

- **Авторизация**: при открытии UI отображается стеклянная страница входа с подсказками по ролям. После входа администратор видит отдельный блок управления логином/паролем операторов.
- **Добавление артикулов**: форма позволяет добавить несколько строк, удалить/добавить новую строку.
- **Ручной режим**: кнопка «Ручное добавление» выполняет поиск/сохранение только первой строки.
- **Режим отладки**: кнопка с иконкой «жучка» или переключатель «Включить режим отладки». При активации отображаются подробные логи (heuristics, совпадения) для каждого результата и записи истории.
- **Темы**: иконка луны/солнца переключает между светлой и тёмной (полупрозрачной) темой Material UI.
- **Индикатор прогресса**: реальный прогресс «Обработано M из N» и статусы этапов (`Internet`, `googlesearch`, `OpenAI`), собранные из ответов сервера; итог остаётся на экране до следующего поиска.
- **Настройки** (администратор): Telegram-бот, chat ID и типы уведомлений (ошибки авторизации внешних API, исчерпание квоты OpenAI/SerpAPI/Google CSE), кнопка тестового сообщения.
- **Импорт/Экспорт**: отдельные стеклянные карточки в правой колонке.
- **Таблица производителей**: отдельная секция с таблицей (`Article`, `Manufacturer`, `Alias`, `Submitted`, `Match`), которая автоматически пополняется при каждом поиске или импорте и синхронизирована с базой данных.
- **Современный UI**: градиентный фон, стеклянные карточки, быстрые действия с иконками и компактные карточки результатов/истории адаптированы для десктопа и мобильных устройств.

### 6. Логика поиска

Подробное описание — в [OPTIMIZED_SEARCH_LOGIC.md](OPTIMIZED_SEARCH_LOGIC.md). Кратко:

1. **Кеш**: если артикул уже определён и подсказка оператора с ним совпадает (или её нет), результат берётся из БД без внешних запросов.
2. **Internet**: запросы `<артикул> <подсказка>` и `<артикул>` выполняются параллельно у первого доступного провайдера (SerpAPI → Yahoo → Bing → DuckDuckGo → Google). Выдача без единого упоминания артикула (капча, «мусорная» анти-бот выдача) отбрасывается и провайдер переключается, а при повторах временно отключается. Сначала анализируются только метаданные (домен, заголовок, сниппет, сегменты URL дистрибьюторов вроде `/detail/stmicroelectronics/LM317T/`); если уверенность < 0.8 — параллельно выполняется запрос `datasheet` и скачиваются 3–4 документа.
3. **googlesearch** (Google Custom Search): только если уверенность после Internet < 0.75.
4. **OpenAI**: только если уверенность < 0.8. Модель получает компактный контекст (≈8 сниппетов + выдержки из документов, ~1000 токенов) и возвращает JSON. Ответ, подтверждённый выдачей, повышает уверенность; неподтверждённый учитывается с пониженным весом. Справочная информация о производителе (страна, продукция, сайт) берётся из встроенного справочника или БД и лишь для неизвестных производителей запрашивается у OpenAI (с кешированием).
5. **Агрегация**: признаки с одного домена не суммируются, голоса разных доменов объединяются как независимые (`1 − Π(1 − w)`); при сопоставимой поддержке нескольких производителей уверенность снижается. Ниже 0.45 производитель не считается найденным.
6. **Сопоставление с подсказкой**: названия приводятся к каноническому виду (алиасы, транслитерация, дочерние бренды), статус `matched`/`mismatch`/`pending` сохраняется вместе с `stage_history`.

Все обращения к поисковикам и OpenAI пишутся в таблицу `search_logs` (ответы обрезаются до 20 000 символов) и доступны на странице «Логи».

### 7. Экспорт/Импорт файлов

- **Excel**: формируется `storage/export.xlsx` с колонками `Article`, `Manufacturer`, `Alias`, `Req.Mnfc`, `Match`, `What Produces`, `Website`, `Manufacturer Aliases`, `Country`.
- **PDF**: альбомный отчёт `storage/export.pdf` с теми же колонками (кириллица — через шрифт DejaVu, который устанавливается в Docker-образ; длинные значения переносятся, строки не разрываются между страницами).
- Каталог `storage/` автоматически создаётся при старте.

### 8. Просмотр логов

- В верхней панели доступна вкладка «Логи» с таблицей запросов/ответов Google Search, Google CSE и OpenAI.
- Фильтруйте записи по провайдеру, типу события (request/response) и подстроке запроса, обновляя выдачу кнопкой «Обновить».
- В таблице показываются время события, статус и полезная нагрузка ответа.

### 9. Дополнительные замечания

- Проект использует асинхронный httpx; включите SOCKS5-прокси через переменные `PROXY_HOST`/`PROXY_PORT` (и `PROXY_USERNAME`/`PROXY_PASSWORD`, если требуется аутентификация).
- Для продакшена рекомендуется заменить SQLite на PostgreSQL и запускать `uvicorn`/`gunicorn` за reverse proxy.
- Все ключи и чувствительные данные храните в `.env` (не коммитится).

## Тестирование

Бэкенд покрыт тестами `pytest` (справочник и сопоставление названий/артикулов, парсеры выдачи, агрегация признаков, поисковый движок с фейковыми провайдерами, API). Внешние сервисы в тестах не вызываются.

```bash
cd backend
pip install -r requirements-dev.txt
```
